# Rise to Panteon — агенту

2D RPG-песочница на Unity 6.6 (6000.6.3f1) для iOS и Android, одиночная. Вся игровая логика — Unity ECS
(Entities 6.6, Burst); отрисовка (URP 2D), UI (UI Toolkit) и сервисы (VContainer) — отдельные контуры, связанные
только данными. Полное описание харнесса — [Docs/Tech/Harness.md](Docs/Tech/Harness.md).

## Знание — через базу `rag`

Документация проекта (~3 МБ) в контекст не помещается. Не читай документы целиком «на всякий случай» — бери нужное
через MCP-сервер `rag`:

- **Перед правкой или созданием файлов** — `context_for_paths([пути])`: запись заметки о типе, шапка среза, правила
  GDD, документ контура, полный текст правил `ARCH`, `CODE` и контура.
- **«Как устроено, где, почему»** — `search("запрос")`, затем `get` нужного раздела.
- **Точное** — `get("SIM-03")`, `get("E01 R3")`, `get("E01")`, `get("Simulation.md#Шаг мира")`, `get("AbsorbSystem")`.
- Найденное — опора, а не замена: файлы, которые меняешь, читай сами; правило цитируй по ID.

| Что | Где |
|---|---|
| Что делает игра | `Docs/GDD/` — README, документы систем, `Features/<ID>-<Name>.md` (правила `Rn`) |
| Как устроен код, правила `ARCH`, `CODE`, `SIM`, `PRES`, `UI`, `CONT`, `SVC` | `Docs/Tech/Architecture/` — `README.md` первым |
| Что делает конкретный код и почему | Заметка: `Features/<Срез>/README.md`, `Code/<Сборка>/[<Область>/]README.md` |
| Что реализовано | `Docs/Roadmap.md` |
| Как работают агенты, правила `DOC`, `WORK` | `Docs/Tech/Harness.md` |
| API Entities, Jobs, Burst 6.6 | `Docs/Tech/Reference/Unity/` |

Не источники: `Docs/Parked/` (отложенное), `Docs/Tech/Reference/WO_*.md` (чужой проект), код
`Assets/_Project/{Dots,Framework,Main,Dev,Editor,Data}` — прототип старой концепции: не менять, не ссылаться, не
брать за образец.

## Жёсткие правила

- **Комментариев в коде нет** — ни в `.cs` (включая `///`), ни в USS, UXML и шейдерах; всё, что хочется написать
  комментарием, — в заметку (CODE-18).
- **Заметка:** каждый `.cs` описан в заметке своей единицы — записью `### <Тип>` или строкой таблицы; изменилось
  поведение — запись обновляется тем же коммитом (CODE-19).
- **Механика изменилась** — файл фичи в `Docs/GDD/Features/` (новая механика — новый файл и строка в
  `Docs/GDD/Features.md`). **Устройство кода изменилось** — журнал решений и документ контура, затем код (ARCH-20).
- **Реализация продвинулась** — строка в `Docs/Roadmap.md` тем же коммитом (CODE-17).
- **Документы:** каждый факт в одном месте, только текущее состояние, без воды (DOC-01…03). Файлов планов, спек,
  отчётов и разборов в репозитории нет (DOC-06): результат работы — правка канонических документов.
- Числа баланса — только в `Configs/`; текст для игрока — только ключи локализации.
- Кодстайл и именование — `CodeStructure.md` §5; куда класть файл — §2 и §6; как добавить фичу — §11.
- Симуляция: `ISystem` + `[BurstCompile]`, работа в джобах; структурные изменения — через ECB тика; случайность —
  `Unity.Mathematics.Random` с состоянием в компонентах; ввод — только `IInputService`.
- Изменяемое `static`-состояние — по CODE-11: в `Simulation` запрещено, в остальных сборках сбрасывается (Enter Play
  Mode без перезагрузки домена).
- Правило GDD неясно или документы противоречат друг другу — остановись и спроси (WORK-02).

## Процесс задачи

1. `context_for_paths` по файлам задачи; при необходимости `search` → `get`.
2. План — в разговоре.
3. Код, тесты, записи заметки, роадмап; GDD и архитектура — если меняются механика или устройство.
4. Проверка: компиляция и тесты Unity (`CodeStructure.md` §9, §12); `uv run --project Tools/rag rag lint --changed`.
5. Ревью: агент `reviewer` на изменения; замечания исправить, спорные вынести человеку (WORK-06).
6. Коммит по `CodeStructure.md` §10; сейчас вся работа идёт в `main`.

Хуки: при чтении `.cs` в контекст приходит запись заметки о файле, при правке — напоминание обновить её; в конце
ответа проверяются изменения сессии (`rag lint`), замечания возвращаются тебе — исправь или объясни человеку, почему
это не проблема.
