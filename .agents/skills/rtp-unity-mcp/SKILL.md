Нормы проекта — [AGENTS.md](../../../AGENTS.md), подключения — [Harness.md](../../../Docs/Tech/Harness.md) §13.2.
Учитывай уже выданное разрешение; наличие пакета Unity MCP само по себе не разрешает запуск редактора или сервера.

## Подключение и выбор проекта

1. Обнаружь фактически доступные инструменты и ресурсы Unity MCP; имена и схемы Claude не подставляй вслепую.
   Если сервера нет, сообщи это и продолжи доступную работу с файлами; не считай Unity-проверку выполненной.
2. После разрешения подключения возьми transport, endpoint или команду из настроек установленного MCP for Unity
   в редакторе. Добавляй только проектную конфигурацию Codex; не копируй глобальные серверы Claude.
3. Прочитай список экземпляров, выбери проект с полным путём текущего workspace и проверь editor state:
   компиляция и domain reload завершены, сервер готов к операциям. При нескольких экземплярах выбор обязателен.

## Выполнение и проверка

- Получи `context_for_paths` для файлов задачи. Для сцены/префаба сначала прочитай иерархию и компоненты,
  найди объекты и используй возвращённые идентификаторы; проходи страницы до конца нужного результата.
- UI проекта — UI Toolkit, отрисовка — URP 2D, игровая симуляция — ECS; универсальные примеры с Canvas,
  MonoBehaviour-логикой и 3D-примитивами не являются проектными шаблонами.
- Сцены и префабы меняй через подходящие операции установленного сервера. Сохраняй `.meta` и GUID;
  перед сохранением проверь путь, после — изменения файлов и console.
- Независимые операции можно объединить в поддерживаемый batch. Зависимые выполняй последовательно;
  ошибку одной операции не скрывай успешным статусом всего batch.
- После правок C# дождись компиляции и прочитай ошибки. Если операция уже запросила импорт/компиляцию,
  повторный refresh не нужен; после внешней правки используй предусмотренный сервером refresh один раз.
- Проверяй визуальный результат снимком сцены/камеры и просмотром изображения. Для ассетов выполни проверки
  [Content.md](../../../Docs/Tech/Architecture/Content.md) §9, для анимации — Presentation.md §5.
- Тесты запускай только в разрешённом объёме: сохрани job ID, дождись завершения и получи итог с ошибками;
  принятие задания не означает прохождение тестов. Аналогично для сборки и импорта.
- При busy/reload дождись готовности; при stale SHA перечитай файл и изменения. После потери соединения
  сначала проверь результат предыдущей операции, чтобы не создать второй объект повторной отправкой.

В ответе укажи изменённые сцены/ассеты, фактические результаты компиляции, тестов и визуальной проверки,
а также оставшееся непроверенным. Архив миграции для выполнения этого skill не требуется.
