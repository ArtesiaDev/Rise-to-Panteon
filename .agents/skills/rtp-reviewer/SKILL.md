Прочитай метод, критерии замечания и формат вердикта в
[общем промпте ревьюера](../../../.claude/agents/reviewer.md).
Его frontmatter `model` и `tools` — настройки Claude, не параметры Codex; метод в теле документа общий.

В Codex:

- Передай ревьюеру задачу и причину изменения, ID фич (если применимы), базовый commit и список файлов,
  включая новые, результаты проверок и ограничения проверки. Без базы используй `HEAD`.
- Для независимого ревью вызывающий агент запускает отдельный контекст с этим skill и указанными входами.
  Сам ревьюер повторно себя не запускает. Если делегирование недоступно, явно отметь самостоятельное ревью.
- Обнаружь доступные инструменты RAG по операциям `context_for_paths`, `get`, `search`, `related`, `lint`:
  префикс MCP зависит от клиента. Локальный RAG разрешён; отсутствие сервера не означает «проверка пройдена».
  Без MCP используй локальный путь запуска из [Harness.md](../../../Docs/Tech/Harness.md) §13.4.
- Читай файлы через доступные средства чтения или shell (`cat`, `sed`, `rg`); Git — только `status`, `diff`,
  `log`, `show`. Новые файлы читай отдельно: обычный `git diff` их содержимое не показывает.
- Ничего не исправляй и не устанавливай, не запускай Unity или внешние сервисы. Unity-проверки, которых нет
  в доказательствах автора, пометь как не выполненные; это не повод запускать их из ревью.
- Для Python, конфигураций, hooks и промптов проверь реальные входы/выходы, обработку ошибок, доступность
  ссылок и соответствие Harness.md; правила игрового C# применяй только к их области действия.

Вердикт из общего промпта включает проверенные файлы, полученные правила, результат lint и границы проверки.
