# Runtime 2D Roguelike (Unity) — PromptBook

Ниже — последовательный набор промтов (ядро + опциональные). **У всех промтов одинаковая структура**:
- **Context**: что уже есть и на что опираемся
- **Task**: что реализовать
- **Constraints**: ограничения/правила реализации
- **Definition of done**: критерии готовности

## Общий Context (для всех промтов)
- Проект Unity 2D (URP2D). В сцене уже есть `SceneContext`, `Main Camera`, `Global Light 2D`.
- Zenject уже подключён; инсталлеры: `Assets/_Project/Scripts/DI/MainInstaller.cs` (SceneContext) и `Assets/_Project/Scripts/DI/ProjectInstaller.cs` (ProjectContext).
- **Все C# скрипты строго в** `Assets/_Project/Scripts/**`.
- Геймплей: **real-time**.
- Контент: **runtime-only** (простая графика тоже генерируется в рантайме; без импортированных спрайтов/тайлов для контента).
- Все сгенерированные игровые объекты должны быть дочерними под `GodObject` (`WorldRoot`, `EntitiesRoot`, `UIRoot`).

## P01 — GodObject + RunController (скелет забега)

**Prerequisites**: none

### Context
В сцене есть служебные объекты (камера/свет/SceneContext). Нужно добавить ровно один игровой root — `GodObject`.

### Task
Сделай компонент `RunController` (или `GodObjectBootstrapper`) на объекте `GodObject`, который:
- хранит `seed` (int) и размеры карты (по умолчанию 200×200)
- на `Start()` создаёт под `GodObject` контейнеры `WorldRoot`, `EntitiesRoot`, `UIRoot`
- запускает пайплайн генерации (пока можно заглушками)
- умеет `RestartRun()` (удалить всё под `GodObject` и сгенерировать заново, с новым seed)

### Constraints
- Служебные объекты сцены не трогать (кроме добавления `GodObject`).
- Все создаваемые во время забега игровые объекты — дети `GodObject`.

### Definition of done
- При старте сцены появляется `GodObject` и 3 контейнера‑ребёнка.
- По горячей клавише или публичному методу можно перезапустить забег без перезагрузки сцены.

## P02 — Runtime SpriteFactory (простая графика без ассетов)

**Prerequisites**: none (можно делать сразу после P01 или параллельно)

### Context
Контент должен быть runtime-only. Нужен единый способ получать спрайты для тайлов/сущностей.

### Task
Реализуй `SpriteFactory`, который создаёт `Sprite` из `Texture2D` (например 16×16) в рантайме:
- разные ключи → разные цвета/узоры (пол/стена/враг/лут/ловушка)
- кэширование: один и тот же ключ возвращает один и тот же `Sprite`

### Constraints
- Не добавлять импортированные текстуры/спрайты для контента.
- Избегать аллокаций каждый кадр (кэш обязателен).

### Definition of done
- Можно запросить спрайт по enum/ключу, и он стабилен между вызовами.
- В профайле/логах нет “создаём Texture2D каждую отрисовку”.

## P03 — MapData 200×200 + типы клеток

**Prerequisites**: none

### Context
Нужна модель данных карты независимо от рендера (Tilemap) и логики сущностей.

### Task
Добавь модель данных карты:
- `CellType` (минимум: Floor, Wall, Obstacle, Hazard, Empty)
- `MapCell` (минимум: `cellType`, `walkable`, `blocksVision`, `dps`/`onEnterDamage` опционально)
- `MapGrid` размером 200×200 с API: `InBounds`, `Get`, `Set`, `IsWalkable`
- заложи несколько слоёв (хотя бы base + obstacle + hazard)

### Constraints
- Хранение должно быть компактным (200×200 — ок; без GameObject на клетку).
- Типы/слои должны позволять расширение (биомы/ловушки/декор позже).

### Definition of done
- `MapGrid` можно создать, заполнить, прочитать, проверить walkable.
- Есть минимальная структура для слоя hazards.

## P04 — Генератор карты (rooms+corridors) + гарантии

**Prerequisites**: P03

### Context
Есть `MapGrid` и `seed`. Нужен детерминированный генератор layout’а.

### Task
Сделай процедурную генерацию rooms+corridors (BSP или аналог) в `MapGrid`:
- детерминированность по `seed`
- гарантированная связность (игрок может пройти в большую часть walkable зон)
- “safe radius” вокруг старта (без врагов/ловушек; можно оставить Floor)
- границы карты — стены

### Constraints
- Генерация не должна зависеть от объектов сцены/рендера.
- В генераторе использовать свой RNG, инициализированный `seed`.

### Definition of done
- Для одного и того же `seed` карта воспроизводится.
- Стартовая позиция попадает в валидную walkable область и не заперта.

## P05 — Runtime TilemapWorldRenderer (отрисовка карты)

**Prerequisites**: P01, P02, P03, P04

### Context
Есть `MapGrid` и `SpriteFactory`. Нужен быстрый рендер 40k клеток.

### Task
Создай под `GodObject/WorldRoot` объекты `Grid` + `Tilemap`(ы) в рантайме и отрисуй `MapGrid`:
- пол/стены/опасности — разными Tilemap слоями
- коллизии стен/препятствий должны работать (TilemapCollider2D + CompositeCollider2D или эквивалент)
- тайлы создаются в рантайме (`ScriptableObject.CreateInstance<Tile>()`) и берут спрайты из `SpriteFactory`

### Constraints
- Нельзя создавать отдельный GameObject на каждую клетку.
- Генерируемые объекты должны быть дочерними под `GodObject`.

### Definition of done
- Карта визуально видна и совпадает с `MapGrid`.
- Стены блокируют перемещение физикой/коллизиями.

## P06 — Игрок (спавн в рантайме) + управление

**Prerequisites**: P01, P03, P04, P05

### Context
Есть отрисованная карта, и есть walkable данные. Нужен игрок.

### Task
Реализуй игрока, который создаётся в рантайме под `GodObject/EntitiesRoot`:
- `PlayerController` (WASD/стрелки)
- real-time движение предпочтительно grid-snapped: шаг к центрам клеток + интерполяция
- коллизии со стенами/препятствиями
- камера следует за игроком (простой follow)

### Constraints
- Не использовать заранее созданные префабы игрока.
- Позиция спавна — валидная walkable клетка из генератора (safe area).

### Definition of done
- Игрок появляется после генерации карты и корректно ходит, упираясь в стены.
- Камера следует за игроком без рывков/ошибок.

## P07 — GridOccupancy + A* pathfinding

**Prerequisites**: P03

### Context
Игрок и враги будут занимать клетки. Врагам нужен поиск пути.

### Task
Добавь систему занятости + навигацию:
- `GridOccupancy` (занятые клетки сущностями) с API “занять/освободить/проверить”
- A* по сетке 4‑соседа поверх walkable + occupancy
- `FindPath(from,to)` → список клеток/координат

### Constraints
- На 200×200 A* должен быть приемлем по времени (кэш/лимиты можно позже, но не делать совсем наивно).
- API должен быть удобен для `EnemyAI` (следующий промт).

### Definition of done
- Можно построить путь от врага до игрока и пройти по нему.

## P08 — Спавн врагов + AI “chase & attack”

**Prerequisites**: P01, P06, P07

### Context
Есть `MapGrid`, `GridOccupancy`, игрок. Нужны враги.

### Task
Сделай `EnemySpawner`:
- размещает врагов по правилам (не в стенах, не в safe radius, не на занятых клетках)
- создаёт врагов в рантайме под `GodObject/EntitiesRoot`

Сделай `EnemyAI`:
- агро по радиусу
- преследование игрока через A* (с обновлением пути по таймеру)
- если рядом — атакует по кулдауну
- если далеко — idle/бродит (простое)

### Constraints
- Враги должны корректно регистрироваться в `GridOccupancy`.
- Не спамить пересчётом пути каждый кадр.

### Definition of done
- Враги спавнятся, находят путь, приближаются и атакуют игрока.

## P09 — Combat/Health/Damage (real-time)

**Prerequisites**: P01, P06, P08

### Context
Есть игрок и враги. Нужен общий слой здоровья/урона.

### Task
Введи:
- `Health` (hp/maxHp, события `OnDamaged`, `OnDied`)
- атака игрока: `DamageDealer`/`Hitbox` по кнопке (кулдаун)
- атака врага по игроку (контактная или хитбокс‑атака)
- смерть врага удаляет его объект и освобождает клетку в `GridOccupancy`

### Constraints
- Урон должен быть детерминированным и не зависеть от FPS (кулдауны по времени).
- Не плодить сложную анимационную систему — достаточно базовой.

### Definition of done
- Есть бой: игрок может убить врага, враг может убить игрока.
- После смерти сущность корректно исчезает и не “занимает” клетку.

## P10 — Лут: выпадение, подбор, простые предметы

**Prerequisites**: P01, P09

### Context
Убийства должны давать награду, а игрок — подбирать предметы.

### Task
Сделай:
- `LootDropper` у врагов (шанс/простая таблица)
- `Pickup` (runtime) — при подборе добавляет золото/хил/XP
- минимальный `PlayerStats`/`Inventory` (хотя бы золото + счётчики расходников)

### Constraints
- Объекты лута — под `GodObject/EntitiesRoot`.
- Подбор должен быть надёжным (триггер/оверлап) и не зависеть от точности FPS.

### Definition of done
- После убийства иногда появляется лут; игрок подбирает; значения меняются.

## P11 — Прокачка: XP, уровни, 3 перка на выбор

**Prerequisites**: P01, P10

### Context
Есть XP из лута/убийств. Нужен интересный прогресс.

### Task
Реализуй:
- `LevelSystem` (XP → уровень)
- при level‑up показать 3 случайных перка на выбор (минимум: +HP, +Damage, +MoveSpeed)
- перки реально влияют на бой/движение

### Constraints
- UI создаётся в рантайме под `GodObject/UIRoot`.
- Перки должны быть расширяемыми (добавлять новые легко).

### Definition of done
- Игрок получает уровень и выбирает перк; эффект виден в игре.

## P12 — Ловушки/опасные тайлы

**Prerequisites**: P01, P03, P04, P05, P06, P09

### Context
Есть hazard‑слой в `MapGrid` и рендер через Tilemap.

### Task
Добавь ловушки:
- `spike`: урон при наступании или периодически пока стоишь
- `poison`: накладывает DoT
Требования:
- ловушки генерируются правилами на карте
- визуально отличаются через `SpriteFactory`/hazard Tilemap

### Constraints
- Ловушки должны триггериться по позиции игрока (по клетке/оверлапу), а не “на глаз”.
- Не смешивать визуальную Tilemap и логику: логика должна опираться на `MapGrid`.

### Definition of done
- На карте есть ловушки, игрок получает урон/эффект при контакте.

## P14 — Баланс/скалирование сложности

**Prerequisites**: P01, P08, P09

### Context
После нескольких минут враги должны становиться опаснее/чаще.

### Task
Добавь “директора” сложности:
- по времени и/или уровню игрока растут статы врагов и/или частота спавна
- параметры регулируемы (в инспекторе на `RunController` или конфигом)

### Constraints
- Не завязывать на Addressables/внешние ассеты.
- Скалирование не должно ломать детерминизм карты (но может менять спавн во времени).

### Definition of done
- В начале проще, позже сложнее; параметры легко менять.

# Опциональные

## Рекомендуемый отбор (real-time + runtime-only)
- **Быстрые и “сильные” по отдаче**: O01 (FOV), O03 (projectiles), O05 (elites), O06 (minimap)
- **Средняя сложность / хорошо усиливают вариативность**: O04 (statuses), O07 (event rooms), O08 (shop)
- **Крупные фичи (делать, когда ядро стабильно)**: O09 (boss + win), O10 (meta-progression), O02 (biomes)

## O01 — Fog of War + FOV

**Prerequisites**: P01, P03, P05, P06

### Context
Хочется “исследование” и напряжение: видеть только вокруг игрока.

### Task
Скрывай тайлы/сущности вне FOV:
- вычисляй видимые клетки (лучи/Bresenham или shadowcasting)
- отображай fog (overlay tilemap или маска)

### Constraints
- Не делать дорогие расчёты каждый кадр: обновление по событию перемещения или раз в N мс.

### Definition of done
- Карта за пределами обзора скрыта/затемнена, сущности вне обзора не видны.
