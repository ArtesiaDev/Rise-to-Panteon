## Контракт контуров (A-13)

**Симуляция → представление и UI.** В конце тика Burst-джоб экспорта пишет в двойной буфер:
- снимок `ViewState { StableId, ViewKey, позиция, направление, анимационное состояние, флаги }`;
- поток событий: удар, смерть, поглощение, звук, реплика;
- read-модели для UI: статы игрока, инвентарь, карта и туман.

Представление читает их через сервис `IWorldView`: сравнивает снимки по `StableId` (появился, исчез, изменился), интерполирует между двумя последними тиками, по `ViewKey` находит ассет в Addressables.

**Ввод, UI, сервисы → симуляция.** Только команды:
- ввод за тик (`PlayerInput`);
- очередь операций `{type, seq, tick, payload}`: действия меню, выбор при эволюции, использование предметов и т. п.

Мостовая система вливает команды в ECS в начале фиксированного тика. Операция проходит Validate → Apply и не порождает другие операции. Лог операций пригоден для воспроизведения багов.

**Хост мира.** Автосоздание мира выключено (`UNITY_DISABLE_AUTOMATIC_SYSTEM_BOOTSTRAP_RUNTIME_WORLD`, `[assembly: DisableAutoCreation]`). Мир создаёт сервис-хост из корня VContainer: явный список систем, включая `UpdateWorldTimeSystem` и ECB-системы, встраивание в PlayerLoop и удаление из него. Мостовые системы (`SystemBase`) создаёт VContainer. Игровой код не читает `World.DefaultGameObjectInjectionWorld`. Burst-системы сервисов не вызывают.

## Рекомендовано

### R-01. Идентичность и детерминизм
Нужны не для сервера, а по GDD:
- `StableId` (ulong) на всём, что сохраняется или на что ссылаются. `Entity.Index` недетерминирован и в сохранения не попадает.
- Шаг мира детерминирован (L01, L03): фиксированный порядок правил, локации по возрастанию id, популяции в fixed-point, случайность только от сида и состояния. Результат не зависит от того, как разбито время.
- Где порядок важен — сортировка по `StableId` (сортировки в Collections нестабильны).

### R-02. Сохранения
По GDD (M01): полный снимок мира, атомарная запись (временный файл → замена) с одной резервной копией, вне главного потока; при сворачивании — пауза и автосохранение. Снимок собирается из ECS джобом экспорта в DTO. Формат — открыто (O-04).

### R-03. Производительность
По умолчанию — Burst-джоб (`IJobEntity`/`IJobChunk`, `ScheduleParallel`); главный поток — только с обоснованием. Структурные изменения — пачками через ECB в отведённых точках. Пространственная сетка для поиска соседей. Бюджеты GDD: 30–40 активных существ на локацию, 40 в одной комнате без просадки FPS на слабом телефоне; переход между локациями ≤ 1 с (≤ 2 с на слабых); догонка шага мира ≤ 100 мс; генерация локации ≤ 0,5 с.

### R-04. Процесс агентов (отложено до обсуждения харнесса)
Из продакшна взять: конституцию «один принцип — один файл», базу знаний со строгим форматом и валидатором, единый вход в задачу, ревью «скептик + инженер», проверку компиляции и тесты. Не брать: десятки пересекающихся скиллов, две конституции, регистрацию фич правкой центральных файлов.
