# Задачи: Фаза 0 + Фаза 1

> Детальный технический план.
> Контекст текущего проекта: один этаж, нет сохранений, нет Game Over экрана, чистая ECS-архитектура (Unity.Entities 1.4.x, Burst, DOTS).

---

## Фаза 0 — Архитектурная подготовка

Цель: подготовить фундамент, без которого невозможно строить многоэтажную систему, Лагерь и прогресс между сессиями.

---

### P0.1 — Стейт-машина забега и многоэтажный RunState

**Что сделать:**
- Добавить в `RunState`:
  - `int FloorNumber` — номер текущего этажа внутри яруса (1..N)
  - `int TierNumber` — номер текущего яруса (0, 1, 2…)
  - `uint BaseSeed` — исходный seed кампании (не меняется между этажами)
  - `FloorPhase Phase` — enum: `Generating | Active | Transitioning | InCamp`
- Производный seed этажа: `floorSeed = math.hash(uint2(BaseSeed, FloorNumber + TierNumber * 1000))`
- MapGenerationSystem должен использовать `floorSeed`, а не `BaseSeed` напрямую
- Инициализация при старте: `TierNumber = 0`, `FloorNumber = 1`, `Phase = Generating`

**Зависит от:** ничего
**Готово когда:** каждый новый этаж генерирует уникальную карту, отличную от предыдущего, но воспроизводимую при одинаковом BaseSeed

---

### P0.2 — Переход между этажами (Floor Transition)

**Что сделать:**
- Новый компонент `FloorTransitionRequest { bool ToNextFloor; bool ToCamp; }`
- Новая система `FloorTransitionSystem` (в SimulationSystemGroup, после RestartSystem):
  - При `ToNextFloor == true`:
    1. Уничтожить все `RunTag`-сущности, кроме игрока
    2. Освободить и пересоздать BlobAsset карты
    3. Сбросить `RunSpawnState`, `RngState`, `DifficultyState`
    4. Инкрементировать `RunState.FloorNumber`
    5. Переключить `RunState.Phase = Generating` → запускает цепочку Init-систем
    6. **HP игрока не восстанавливается** — сохраняется как есть
  - При `ToCamp == true`: переключить `RunState.Phase = InCamp`
- Проверка: PlayerStats (Level, XP, Gold) переносятся между этажами без изменений

**Зависит от:** P0.1
**Готово когда:** игрок может перейти с этажа 1 на этаж 2 с сохранением своего прогресса и новой картой

---

### P0.3 — Game Over экран и возврат в Лагерь

**Что сделать:**
- Добавить `GameOverState { bool IsActive; int FloorsReached; int EnemiesKilled; }` в RunState
- Модифицировать `DeathSystem`: при гибели игрока → `GameOverState.IsActive = true`, не сбрасывать автоматически
- Новый `GameOverUiBridge` (Hybrid/UI):
  - Показывает оверлей: «Вы пали» + краткая статистика (этаж, враги)
  - Кнопка **«Вернуться в Лагерь»** → устанавливает `FloorTransitionRequest.ToCamp = true`
  - Кнопка **«Начать заново»** (старый рестарт, для дебага/прототипа)
- Убрать текущую автоматическую логику «нажми R для рестарта» из основного flow (оставить только как dev shortcut)

**Зависит от:** P0.1, P0.2
**Готово когда:** при гибели появляется экран с двумя кнопками; ни одна система не запускается в фоне до выбора игрока

---

### P0.4 — Сцена / режим Лагеря (скелет)

**Что сделать:**
- Определить архитектуру: **additive scene loading** (Camp.unity поверх Main.unity) или отдельный ECS World — *рекомендую additive сцену, т.к. ECS World один и синглтоны сохраняются*
- Создать `Camp.unity` — пустая сцена с Canvas и базовым Camera
- `CampUiBridge` (Hybrid):
  - Активируется при `RunState.Phase == InCamp`
  - Показывает заглушку «Лагерь» с кнопкой «Идти в ярус» (следующий или выбранный)
- `CampTransitionSystem`:
  - При нажатии «Идти в ярус» → устанавливает `FloorNumber = 1` (всегда начинаем ярус с 1 этажа), переключает Phase → `Generating`
  - При входе в Лагерь после **смерти**: `TierNumber` не меняется — тот же ярус начинается заново с этажа 1
  - При входе в Лагерь после **победы над Стражем**: инкрементировать `TierNumber`, `FloorNumber = 1`
  - Выгружает Camp-сцену, запускает Main

**Зависит от:** P0.1, P0.2
**Готово когда:** после смерти или завершения яруса → Лагерь (пустой экран), из Лагеря → обратно в ярус

---

### P0.5 — Система сохранений (Session Persistence)

**Что сделать:**
- Определить **что сохраняется** между сессиями: `TierNumber`, `FloorNumber`, `PlayerStats (Level, XP, Gold)`, `BaseSeed кампании`
- Создать `CampaignSaveData` — plain C# struct, сериализуется в JSON через `JsonUtility`
- `SaveSystem` (MonoBehaviour, singleton, не ECS):
  - `Save()` — сериализует и записывает в `Application.persistentDataPath/save.json`
  - `Load()` → десериализует, инжектирует в RunState при старте через `ConfigBridge`
  - Авто-сохранение при: входе в Лагерь, выходе в яруса, закрытии приложения
- Загрузка при старте: если файл сохранения есть → продолжить кампанию; если нет → новая кампания с рандомным BaseSeed

**Зависит от:** P0.4
**Готово когда:** прогресс (ярус, уровень) сохраняется при закрытии и восстанавливается при перезапуске приложения

## Фаза 1 — Структура подземелья

Цель: превратить один этаж в полноценную многоэтажную систему с боссами, биомами и порталами.

---

### P1.1 — Лестницы / выход с этажа

**Что сделать:**
- Новый тип ячейки: `MapCellType.Staircase`
- Новый компонент `StaircaseTag`
- Модификация `MapGenerationSystem`:
  - Найти «самую дальнюю» от Start комнату (по Euclidean distance до центра)
  - Разместить Staircase в центре этой комнаты
  - Старкейс не ставится, если текущий этаж — последний в ярусе (там будет Страж Порога)
- `StaircaseInteractionSystem`:
  - Проверяет, что игрок стоит на ячейке с `StaircaseTag`
  - Устанавливает `FloorTransitionRequest.ToNextFloor = true`
- Рендер: отдельный тайл для Staircase в TilemapRenderBridge

**Зависит от:** P0.1, P0.2
**Готово когда:** игрок доходит до лестницы → переход на следующий этаж с новой картой

---

### P1.2 — Типы комнат: Boss-room и расстановка по этажам

**Что сделать:**
- Добавить в `RoomType`: `MiniBoss`, `ThresholdGuardian`
- Модификация `MapGenerationSystem` с учётом `FloorNumber`:
  - `FloorNumber % 5 == 0` И не последний этаж яруса → самая дальняя комната = `MiniBoss`
  - `FloorNumber == LastFloorOfTier` → самая дальняя комната = `ThresholdGuardian`
  - Иначе → самая дальняя = `Staircase` (обычный переход)
- Отдельный SpawnConfig для MiniBoss-комнаты (увеличенный HP/DMG множитель)
- `LastFloorOfTier` вычисляется из конфига (берётся из таблицы ярусов: TierNumber → floorCount)
- Добавить `TierConfigData`: массив `{ TierNumber, FloorCount, BiomeType }` в конфиге
- **MVP**: Тир 0 = **3 этажа** (этаж 1 и 2 — обычные, этаж 3 — Страж Порога; мини-босс в MVP не попадает, появится с Тира где 5+ этажей)

**Зависит от:** P1.1
**Готово когда:** на 5-м этаже стабильно спавнится мини-босс, на последнем — комната Стража (пустая пока)

---

### P1.3 — Мини-босс

**Что сделать:**
- Новый компонент `MiniBossTag`
- Новый компонент `MiniBossState { int Phase; bool IsEnraged; }`
- `MiniBossSpawnSystem` (InitializationGroup):
  - Ищет комнату с `RoomType.MiniBoss`
  - Спавнит усиленного врага с `MiniBossTag`
  - Масштаб: `HP = base * 8`, `Damage = base * 2`, `Size = 2x2` (или визуально крупнее через рендер)
- Рендер: отдельный спрайт или увеличенный scale через `SpriteRenderBridge`
- Лут: мини-босс при смерти дропает гарантированный ресурс (тип ресурса — заглушка для Фазы 6)

**Зависит от:** P1.2
**Готово когда:** на 5-м этаже в boss-комнате стоит один крупный враг с повышенными stats; при смерти дропает лут

---

### P1.4 — Страж Порога (Threshold Guardian)

**Что сделать:**
- Новый компонент `ThresholdGuardianTag`
- Новый компонент `BossState { int Phase; float PhaseHpThreshold; bool DialogueDone; FixedString64 BossName; }`
- `ThresholdGuardianSpawnSystem`:
  - Спавнит в комнате `ThresholdGuardian`
  - HP = `base * 20`, Damage = `base * 3`
  - `BossName` = из конфига (по TierNumber: набор имён для каждого яруса)
- `BossDialogueSystem` (Hybrid, однократный триггер):
  - При входе игрока в комнату Стража → показывает HUD-оверлей с именем и репликой
  - Реплика — из `BossDialogueConfig SO` (одна строка на ярус, заглушки на старте)
  - После 3 секунд или тапа — скрывается, бой начинается
- Смерть Стража: устанавливает `BossState.Phase = -1` → триггерит спавн Портала Фронтира

**Зависит от:** P1.2
**Готово когда:** на последнем этаже яруса стоит Страж, при входе — показывает имя/реплику, при гибели — появляется портал

---

### P1.5 — Портал Фронтира

**Что сделать:**
- Новый компонент `FrontierPortalTag`
- `FrontierPortalSpawnSystem`:
  - Слушает гибель Стража (`BossState.Phase == -1`)
  - Спавнит портальную сущность в центре комнаты
- `FrontierPortalInteractionSystem`:
  - Игрок входит в ячейку портала → `FloorTransitionRequest.ToCamp = true`
  - Портал активируется только после гибели Стража
- Рендер: отдельный тайл/спрайт

**Зависит от:** P1.4, P0.2, P0.4
**Готово когда:** убив Стража → появляется портал → игрок заходит → попадает в Лагерь; TierNumber инкрементируется при переходе

---

### P1.6 — Обновление HUD

**Что сделать:**
- Добавить в `HudBridge`:
  - Индикатор «Ярус N / Этаж M» (из `RunState.TierNumber` и `RunState.FloorNumber`)
  - HP-бар босса (активируется при наличии `ThresholdGuardianTag` или `MiniBossTag`; скрывается иначе)
- Экран перехода между этажами (`FloorTransitionUiBridge`):
  - При `Phase == Transitioning` показывает fade + текст «Этаж N»
  - Исчезает после завершения генерации (`Phase == Active`)
- Переработать Restart-кнопку: убрать из основного HUD в dev overlay (F5)

**Зависит от:** P0.1, P0.3, P1.4
**Готово когда:** на экране всегда виден текущий ярус/этаж; бар босса появляется при боссе

---

### P1.7 — Базовые биомы (Тиры 0–2)

**Что сделать:**
- Создать `BiomeConfig SO` с полями:
  - `BiomeType` (enum: Abyss, Catacombs, CrystalDepths …)
  - Наборы тайлов (Floor, Wall, Hazard)
  - `FogColor`, `AmbientIntensity`
  - `EnemyHpMultiplier`, `EnemyDamageMultiplier` (базовый биомный масштаб)
- Создать конфиги для биомов 0, 1, 2 (Бездна, Катакомбы Забытых, Кристальные Недра)
- Добавить `TierConfigData.BiomeType` → `TilemapRenderBridge` выбирает нужный `BiomeConfig` по текущему `TierNumber`
- FogRenderBridge: применять `FogColor` из активного биома
- Минимальное визуальное отличие: 3 разных сета тайлов (floor + wall), разный туман

**Зависит от:** P0.1
**Готово когда:** ярусы 0, 1, 2 визуально отличаются цветом тайлов и туманом

---

### P1.8 — Сложность по этажам

**Что сделать:**
- Модифицировать `DifficultyConfigData`: добавить `FloorDifficultyScale` (AnimationCurve или float per-floor multiplier)
- Модифицировать `DifficultyTickSystem`:
  - Базовый multiplier = `f(TierNumber, FloorNumber)` вместо только времени
  - Формула: `totalMultiplier = timeMultiplier * (1 + FloorNumber * 0.1f) * (1 + TierNumber * 0.3f)`
- `EnemySpawnUtilities`: учитывать новый multiplier при генерации HP/Damage врагов
- Тест: на этаже 5 яруса 0 враги заметно сильнее, чем на этаже 1

**Зависит от:** P0.1
**Готово когда:** враги масштабируются по ярусу и этажу, не только по времени внутри сессии

## Решения по открытым вопросам

| # | Вопрос | Решение |
|---|--------|---------|
| Q1 | HP при переходе между этажами | Сохраняется как есть, не восстанавливается |
| Q2 | При смерти — тот же ярус или новый? | Тот же ярус, этаж 1 |
| Q3 | Этажей в Тире 0 для MVP | 3 этажа |
| Q4 | Надписи на стенах (асинхронный мультиплеер) | Шаблонные фразы (как Dark Souls); задача дальняя, не влияет на архитектуру сейчас |
